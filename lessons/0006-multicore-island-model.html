Part 6 • Concurrency & Scaling

Multi-Core Island Model & $(1+\lambda)$ Strategy

Harness modern multi-core processors by distributing candidate evaluations across parallel worker pools and running independent island demes with periodic champion migration.

1 The Single-Core Bottleneck

In Lesson 4, we constructed a single-threaded (1+1) Hill Climber. While executing 5,000 to 10,000 generations per second on a single thread is impressive, modern workstations have 8, 16, or more CPU cores sitting completely idle.

Why not simply share our global best Painting across threads with a lock?

⚠️ The Shared-State Contention Trap

If multiple threads continuously attempt to read, mutate, and write to a single synchronized Painting, CPU cores waste hundreds of clock cycles contending for memory bus access and invalidating L1/L2 hardware caches. Lock synchronization turns a parallel workload back into a serial queue.

To scale evolutionary computing linearly with hardware cores, we must employ two battle-tested strategies: parallel batch evaluation via \((1+\lambda)\) and demographic isolation via the Island Model.

2 The \((1+\lambda)\) Evolution Strategy

Instead of producing a single mutant per step, the \((1+\lambda)\) Evolution Strategy generates \(\lambda\) independent mutant offspring from the current champion in parallel:

\[ P_{candidate}^{(k)} = \text{mutate}(P_{parent}), \quad k \in \{1, 2, \dots, \lambda\} \]

Each worker thread receives one mutant \(P_{candidate}^{(k)}\), renders it into an isolated headless Skia surface, and computes its fitness \(F(P_{candidate}^{(k)})\). The master loop then gathers all results and selects the fittest mutant:

\[ P_{best} = \arg\min_{k} F(P_{candidate}^{(k)}) \] \[ P_{parent} \leftarrow \begin{cases} P_{best} & \text{if } F(P_{best}) \le F(P_{parent}) \\ P_{parent} & \text{otherwise} \end{cases} \]

With \(\lambda\) equal to the number of logical CPU cores, each generation evaluates multiple exploration vectors simultaneously, significantly increasing the probability of discovering an advantageous mutation on flat error landscapes.

3 Island Model Architecture

While \((1+\lambda)\) accelerates step evaluation, it still suffers from premature convergence: all offspring originate from the same single lineage. If that lineage gets trapped in a local visual optimum (e.g., placing a large dark stroke in the wrong quadrant), the entire population stalls.

The Island Model (coarse-grained parallel genetic algorithm) solves this by partitioning the evolutionary process into \(N\) independent subpopulations called demes:

🏝️ Isolated Demes

Each island runs its own independent \((1+1)\) evolutionary loop on a dedicated thread, exploring distinct artistic trajectories and stroke placements without interference.

🔄 Asynchronous Migration

Every \(M\) generations (e.g., every 2,500 generations), each island exports its current champion to a neighbor. Migrants inject fresh genetic diversity into stagnating demes.

💡 Architecture Choice: Fine-Grained \((1+\lambda)\) vs. Coarse-Grained Island Model

Both Section 2 and Section 3 use \(N\) CPU cores, but they partition the work differently:

  • Fine-Grained Parallelism (\((1+\lambda)\) Batch Evaluation): All \(N\) threads evaluate \(\lambda\) mutations of the same parent every generation, then synchronize at a barrier to pick the best child. Great for raw step speed, but all cores share one lineage and synchronize every step.
  • Coarse-Grained Parallelism (Island Model): Each of the \(N\) threads runs an independent \((1+1)\) loop on its own island with zero barrier synchronization, communicating only every \(M\) generations via lock-free atomic mailboxes. This is the architecture we implement in IslandCoordinator.kt below because it maximizes both thread throughput and phenotypic diversity.

4 Migration Topologies

The arrangement of communication channels between islands is called the migration topology. In genetic art, the most effective structure is the Unidirectional Ring:

\[ \text{Island } 0 \longrightarrow \text{Island } 1 \longrightarrow \text{Island } 2 \longrightarrow \text{Island } 3 \longrightarrow \text{Island } 0 \]

A ring topology ensures slow, controlled diffusion of genetic material. If Island 0 develops a breakthrough representation for eye details, that solution will not instantly flood all islands; rather, other islands maintain their unique background stylings while gradually assimilating the innovation.

6 Kotlin Multi-Core Worker Pool

Here is how to design a non-blocking multi-island coordinator in Kotlin that plugs directly into our Phase 1 TargetImage, Evaluator, and Painting classes using Executors.newFixedThreadPool and lock-free atomic mailboxes:

IslandCoordinator.kt 
import java.util.concurrent.Executors
import java.util.concurrent.atomic.AtomicReference
import java.util.concurrent.atomic.AtomicReferenceArray
import kotlin.random.Random

class IslandCoordinator(
    val numIslands: Int = Runtime.getRuntime().availableProcessors(),
    val target: TargetImage,
    val strokeCount: Int = 150,
    val migrationInterval: Long = 2000L
) {
    // Thread pool with one daemon worker per CPU core
    private val pool = Executors.newFixedThreadPool(numIslands) { runnable ->
        Thread(runnable).apply { isDaemon = true }
    }

    // Migration inboxes: each island has a lock-free slot for incoming champions
    private val migrationInboxes = AtomicReferenceArray<Painting>(numIslands)

    // Global best champion exposed to the Skiko render thread
    val globalChampion = AtomicReference<Painting>()

    fun start() {
        for (islandId in 0 until numIslands) {
            pool.submit {
                runIslandLoop(islandId)
            }
        }
    }

    private fun runIslandLoop(id: Int) {
        // Each island owns its private Evaluator (and offscreen Skia Bitmap)
        val evaluator = Evaluator(target.width, target.height, target.pixelBytes)
        val rng = Random(System.nanoTime() + id * 10_000L)
        val w = target.width.toFloat()
        val h = target.height.toFloat()

        val initial = Painting.createRandom(strokeCount, w, h, rng)
        var localBest = initial.copy(error = evaluator.evaluate(initial))
        globalChampion.accumulateAndGet(localBest) { prev, next ->
            if (prev == null || next.error < prev.error) next else prev
        }

        var generation = 0L

        while (!Thread.currentThread().isInterrupted) {
            generation++

            // 1. Check if our ring neighbor deposited a migrant champion in our inbox
            val migrant = migrationInboxes.getAndSet(id, null)
            if (migrant != null && migrant.error < localBest.error) {
                localBest = migrant
            }

            // 2. Standard (1+1) mutation step within this island
            val mutated = localBest.mutate(w, h, rng)
            val candidateError = evaluator.evaluate(mutated)

            if (candidateError <= localBest.error) {
                localBest = mutated.copy(error = candidateError)

                // Atomically publish to globalChampion without re-evaluating on the CPU
                globalChampion.accumulateAndGet(localBest) { prev, next ->
                    if (prev == null || next.error < prev.error) next else prev
                }
            }

            // 3. Periodic migration: send champion to next island in ring topology
            if (generation % migrationInterval == 0L) {
                val nextIsland = (id + 1) % numIslands
                migrationInboxes.set(nextIsland, localBest)
            }
        }
    }
}

7 Automated Testing & Verification

Multi-core architectures must be tested for thread confinement, monotonic convergence under asynchronous ring migration, and clean thread pool lifecycle termination:

src/test/kotlin/IslandCoordinatorTest.kt 
import kotlin.test.Test
import kotlin.test.assertEquals
import kotlin.test.assertNotNull
import kotlin.test.assertTrue

class IslandCoordinatorTest {
    private val width = 64
    private val height = 64

    @Test
    fun testIslandInitialization() {
        val target = TargetImage.loadOrGenerate(null, width, height)
        val coordinator = IslandCoordinator(numIslands = 4, target = target, strokeCount = 20)

        assertEquals(4, coordinator.numIslands)
        assertEquals(20, coordinator.strokeCount)
        assertEquals(0L, coordinator.totalGenerations.get())
    }

    @Test
    fun testConcurrentEvolutionAndGlobalChampion() {
        val target = TargetImage.loadOrGenerate(null, width, height)
        val coordinator =
            IslandCoordinator(
                numIslands = 3,
                target = target,
                strokeCount = 20,
                migrationInterval = 20L,
            )

        coordinator.start()
        val start = System.currentTimeMillis()
        while (coordinator.totalGenerations.get() < 150L && System.currentTimeMillis() - start < 3000L) {
            Thread.sleep(20)
        }
        coordinator.stop()

        val champion = coordinator.globalChampion.get()
        assertNotNull(champion, "Global champion must be present after concurrent execution")
        assertTrue(coordinator.totalGenerations.get() >= 100L, "Should have executed at least 100 total generations")
        assertTrue(coordinator.acceptedMutations.get() > 0L, "Should have accepted mutations")
        assertTrue(champion.error < Long.MAX_VALUE, "Champion error must be a valid evaluated value")
    }

    @Test
    fun testCleanStopLifecycle() {
        val target = TargetImage.loadOrGenerate(null, width, height)
        val coordinator = IslandCoordinator(numIslands = 2, target = target, strokeCount = 10)

        coordinator.start()
        assertTrue(coordinator.isRunning.get())
        Thread.sleep(50)
        coordinator.stop()
        assertEquals(false, coordinator.isRunning.get())
    }
}
