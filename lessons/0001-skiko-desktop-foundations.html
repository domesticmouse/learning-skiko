Building a Kotlin Desktop App with Skiko

A complete from-scratch tutorial for building high-performance 2D hardware-accelerated desktop apps from the command line without IntelliJ.

Kotlin 2.1+ Skiko / Skia CLI & Gradle macOS / Linux / Windows PrismJS Highlighted

1 What is Skiko?

Skiko (short for Skia for Kotlin) is an open-source library created by JetBrains that exposes multiplatform Kotlin bindings for Google Skia.

Skia is the industry-standard 2D vector graphics engine powering Google Chrome, Android, Flutter, and Jetpack Compose / Compose Multiplatform. With Skiko, you can draw directly onto a hardware-accelerated canvas (using Metal on macOS, DirectX on Windows, and OpenGL/Vulkan on Linux) with absolute precision and blistering speed.

Your Logic & Event Handlers

💡 Why use Skiko standalone without Compose?
While Compose Multiplatform is built on top of Skiko, using Skiko standalone gives you direct, low-overhead access to raw 2D graphics primitives (canvases, paths, shaders, matrix transforms, particle systems, high-FPS game rendering) without the recomposition overhead of a declarative UI framework.

2 Command-Line Prerequisites

Because you are developing strictly from the terminal without an IDE, you will need two tools: a Java Development Kit (JDK 17+) and Gradle.

On macOS (via Homebrew):

Gradle is the standard build tool used for Kotlin projects.

# Check Gradle version:
gradle -v

Every standard Kotlin/Gradle project follows a predictable directory convention. Let's create our workspace and file tree completely from the shell:

4 Configuring Gradle for Skiko

First, specify the project name in settings.gradle.kts:

settings.gradle.kts 
rootProject.name = "skiko-desktop-demo"

Understanding Skiko Dependencies

Skiko is composed of two parts:

  1. org.jetbrains.skiko:skiko-awt: The Java/Kotlin API (classes like Canvas, Paint, SkiaLayer).
  2. org.jetbrains.skiko:skiko-awt-runtime-<os>-<arch>: The native compiled C++ binary containing Skia compiled for your specific OS and CPU architecture (e.g. macos-arm64 for Apple Silicon, macos-x64 for Intel Mac, windows-x64, linux-x64).

Here is our complete, production-ready build.gradle.kts that automatically detects your OS and CPU architecture at build time:

build.gradle.kts 
plugins {
    // 1. Apply the Kotlin JVM plugin
    kotlin("jvm") version "2.1.0"
    // 2. Apply the Application plugin for runnable CLI apps
    application
    // 3. Apply the ktlint plugin for code formatting & style checks
    id("org.jlleitschuh.gradle.ktlint") version "12.2.0"
}

repositories {
    mavenCentral()
    // JetBrains Space repo where official Skiko builds are published
    maven("https://maven.pkg.jetbrains.space/public/p/compose/dev")
}

val skikoVersion = "0.8.18"

// 4. Dynamically detect the host OS
val osName = System.getProperty("os.name")
val targetOs =
    when {
        osName == "Mac OS X" -> "macos"
        osName.startsWith("Win") -> "windows"
        osName.startsWith("Linux") -> "linux"
        else -> error("Unsupported OS: $osName")
    }

// 5. Dynamically detect the host CPU architecture
val osArch = System.getProperty("os.arch")
val targetArch =
    when (osArch) {
        "x86_64", "amd64" -> "x64"
        "aarch64" -> "arm64"
        else -> error("Unsupported architecture: $osArch")
    }

val skikoTarget = "$targetOs-$targetArch"

kotlin {
    jvmToolchain(21)
}

dependencies {
    // Core Skiko AWT bindings
    implementation("org.jetbrains.skiko:skiko-awt:$skikoVersion")
    
    // Platform-specific native binary runtime (e.g. skiko-awt-runtime-macos-arm64)
    implementation("org.jetbrains.skiko:skiko-awt-runtime-$skikoTarget:$skikoVersion")
}

application {
    // Defines the entry point when running `./gradlew run`
    mainClass.set("MainKt")
}

ktlint {
    version.set("1.5.0")
    android.set(false)
    outputToConsole.set(true)
    reporters {
        reporter(org.jlleitschuh.gradle.ktlint.reporter.ReporterType.PLAIN)
        reporter(org.jlleitschuh.gradle.ktlint.reporter.ReporterType.HTML)
    }
}

5 How Skiko Works Under the Hood

On desktop (JVM), Skiko integrates seamlessly with Java Swing / AWT. This is beneficial because Swing provides standard cross-platform window management, window borders, menus, and mouse/keyboard event loops.

The Three Key Concepts
  • JFrame: The operating system window container.
  • SkiaLayer: A specialized Swing component that hosts the GPU-accelerated Skia surface.
  • SkikoRenderDelegate: An interface containing the callback onRender(canvas, width, height, nanoTime) called whenever the frame needs to be drawn.

Inside onRender, you receive a Skia Canvas. Every drawing operation (such as canvas.drawCircle(...) or canvas.drawString(...)) is recorded and rendered directly by the GPU.

6 Writing the First Skiko Application

Now let's implement src/main/kotlin/Main.kt. This sample creates an animated, interactive desktop application that:

  • Opens an 800x600 window centered on screen
  • Renders a dark modern background
  • Draws a smooth pulsing animated circle using nanoTime
  • Follows your mouse cursor smoothly across the canvas
  • Draws anti-aliased vector typography using Skia's Font and Typeface
src/main/kotlin/Main.kt 
import org.jetbrains.skiko.SkiaLayer
import org.jetbrains.skiko.SkikoRenderDelegate
import org.jetbrains.skia.Canvas
import org.jetbrains.skia.Color
import org.jetbrains.skia.Paint
import org.jetbrains.skia.Font
import org.jetbrains.skia.Typeface
import org.jetbrains.skia.Rect
import java.awt.Dimension
import java.awt.event.MouseEvent
import java.awt.event.MouseMotionAdapter
import javax.swing.JFrame
import javax.swing.SwingUtilities
import javax.swing.WindowConstants
import kotlin.math.sin

fun main() {
    // 1. Swing UI creation must always be scheduled on the Event Dispatch Thread (EDT)
    SwingUtilities.invokeLater {
        val window = JFrame("Kotlin Desktop with Skiko").apply {
            defaultCloseOperation = WindowConstants.EXIT_ON_CLOSE
            preferredSize = Dimension(800, 600)
        }

        // Coordinates for interactive cursor tracking
        var mouseX = 400f
        var mouseY = 300f

        // 2. Create the SkiaLayer
        val skiaLayer = SkiaLayer()

        // 3. Attach our custom render delegate
        skiaLayer.renderDelegate = object : SkikoRenderDelegate {
            // Allocate Paints and Fonts once outside the loop for high performance
            val bgPaint = Paint().apply { color = 0xFF1E1E2E.toInt() }
            val circlePaint = Paint().apply {
                color = 0xFF89B4FA.toInt()
                isAntiAlias = true
            }
            val glowPaint = Paint().apply {
                color = 0x55F38BA8.toInt()
                isAntiAlias = true
            }
            val textPaint = Paint().apply {
                color = 0xFFCDD6F4.toInt()
                isAntiAlias = true
            }
            val titleFont = Font().apply { size = 24f }
            val subFont = Font().apply { size = 14f }

            override fun onRender(canvas: Canvas, width: Int, height: Int, nanoTime: Long) {
                // Clear the background
                canvas.drawRect(Rect.makeWH(width.toFloat(), height.toFloat()), bgPaint)

                // Compute smooth elapsed time animation
                val seconds = nanoTime / 1_000_000_000.0
                val pulse = (sin(seconds * 3.0).toFloat() + 1f) * 15f + 40f

                // Draw outer glow and main interactive follower circle
                canvas.drawCircle(mouseX, mouseY, pulse + 20f, glowPaint)
                canvas.drawCircle(mouseX, mouseY, pulse, circlePaint)

                // Draw high-DPI crisp vector text
                canvas.drawString("Hello from Skiko (Skia for Kotlin)!", 50f, 70f, titleFont, textPaint)
                canvas.drawString("Move your mouse around to interact with the hardware canvas.", 50f, 105f, subFont, textPaint)
                canvas.drawString("Resolution: ${width}x${height}px | Time: ${String.format("%.1f", seconds)}s", 50f, height - 30f, subFont, textPaint)

                // Request continuous redrawing for 60fps/120fps animation
                skiaLayer.needRedraw()
            }
        }

        // 4. Listen to mouse motion events
        skiaLayer.addMouseMotionListener(object : MouseMotionAdapter() {
            override fun mouseMoved(e: MouseEvent) {
                mouseX = e.x.toFloat()
                mouseY = e.y.toFloat()
                skiaLayer.needRedraw()
            }
        })

        // 5. Mount the SkiaLayer into the JFrame window
        skiaLayer.attachTo(window.contentPane)
        window.pack()
        window.setLocationRelativeTo(null) // Center window on screen
        window.isVisible = true
    }
}

8 Building and Running From the CLI

With our files in place, we can execute the application directly from the command line using Gradle.

1. Generate the Gradle Wrapper

The Gradle Wrapper ensures that anyone can run the project without needing Gradle pre-installed:

Terminal 
gradle wrapper

2. Run the App

Run the application with one command:

Terminal 
./gradlew run
💡 Running in the background or with custom arguments
If you want to pass JVM memory limits or flags: 
./gradlew run --args="--fullscreen" -Dorg.gradle.jvmargs="-Xmx1024m"

3. Building an Executable Distribution

The application plugin provides a built-in task to package your app into a standalone tar/zip archive with startup shell scripts for macOS/Linux and .bat files for Windows:

Terminal 
# Package the distribution
./gradlew installDist

# Run the packaged standalone executable
./build/install/skiko-desktop-demo/bin/skiko-desktop-demo

9 Code Formatting & Linting with Ktlint

When working outside of IntelliJ (such as in VS Code, Neovim, Helix, or standard terminal editors), you don't have IntelliJ's automatic Cmd+Option+L formatter running in the background. In the Kotlin ecosystem, ktlint is the industry-standard linter and formatter that adheres strictly to the official Kotlin coding conventions.

💡 Why Ktlint?
Ktlint operates on an anti-bikeshedding philosophy: it enforces official language rules with zero arguments over tabs vs spaces or brace styles, ensuring a consistent codebase across team members and CI pipelines.

1. Automated In-Place Formatting

Run the formatting task to automatically fix indentation, spacing, multiline expressions, import order, and trailing commas across all .kt and .gradle.kts files:

Terminal 
./gradlew ktlintFormat

2. Verifying Code Style (Linting)

Run the check task to scan your project for style violations without modifying any files (ideal for CI/CD checks):

Terminal 
./gradlew ktlintCheck

When violations are found, ktlint prints the exact file, line number, and rule violation to the console, and generates detailed HTML and plain-text reports in build/reports/ktlint/.

3. Optional: Standalone CLI & Pre-commit Hooks

You can also install ktlint directly on macOS via Homebrew to format files without running Gradle:

Terminal (Homebrew CLI) 
# Install standalone ktlint CLI
brew install ktlint

# Format a file directly
ktlint -F "src/**/*.kt"

# Automatically install a Git pre-commit hook that prevents committing unformatted code
ktlint installGitPreCommitHook

10 Essential Skia API Quick Reference

Here are common Skia drawing techniques you can plug into your onRender loop:

1. Linear Gradient Shaders

Kotlin (Gradients) 
import org.jetbrains.skia.Shader
import org.jetbrains.skia.Point

val gradientShader = Shader.makeLinearGradient(
    x0 = 0f, y0 = 0f,
    x1 = 400f, y1 = 400f,
    colors = intArrayOf(0xFFf38ba8.toInt(), 0xFF89b4fa.toInt())
)
val gradientPaint = Paint().apply {
    shader = gradientShader
    isAntiAlias = true
}

canvas.drawRoundRect(50f, 50f, 350f, 250f, 20f, 20f, gradientPaint)

2. Custom Vector Paths & Curves

Kotlin (Paths) 
import org.jetbrains.skia.Path

val path = Path().apply {
    moveTo(100f, 300f)
    cubicTo(150f, 200f, 250f, 400f, 300f, 300f)
    lineTo(300f, 350f)
    closePath()
}

val strokePaint = Paint().apply {
    color = 0xFFA6E3A1.toInt()
    mode = org.jetbrains.skia.PaintMode.STROKE
    strokeWidth = 4f
    isAntiAlias = true
}

canvas.drawPath(path, strokePaint)

11 Common Command-Line Pitfalls

⚠️ Pitfall 1: "Unable to locate a Java Runtime" on macOS

When installing OpenJDK through Homebrew, macOS's system wrapper (/usr/bin/java) does not automatically recognize the Homebrew symlink unless you export PATH or create a system symlink:

export PATH="/opt/homebrew/opt/openjdk/bin:$PATH"
export JAVA_HOME="/opt/homebrew/opt/openjdk"
⚠️ Pitfall 2: UnsatisfiedLinkError / Native Skiko Binary Mismatch

If you see java.lang.UnsatisfiedLinkError: no skiko-macos-arm64 in java.library.path, it means the runtime classifier in build.gradle.kts doesn't match your JVM. For example, if you run an x86_64 JVM under Rosetta on an M1/M2/M3 Mac, os.arch will be x86_64 instead of aarch64. Always ensure your JDK architecture matches your native machine architecture.

💡 Pitfall 3: High-DPI / Retina Displays

Skiko handles DPI scaling automatically, but keep in mind that width and height passed to onRender are in physical pixels, while Swing event coordinates may be in logical points. skiaLayer.contentScale gives you the current pixel scaling factor (e.g. 2.0 on Retina screens).
