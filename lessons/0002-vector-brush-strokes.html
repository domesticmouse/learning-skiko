Part 2 • Genetic Representation

Vector Brush Strokes & Genotype Representation

Learn how to model visual artwork as digital DNA in Kotlin, render smooth curved brush strokes using Skiko's 2D vector path APIs, and design stochastic mutation operators.

1 Genotype vs. Phenotype in Genetic Art

In biological evolution, an organism's genotype is its genetic code (DNA sequence), while its phenotype is the physical organism expressed in the environment.

In procedural genetic art, we maintain the exact same distinction:

🧬 Genotype (The Code)

A compact data structure representing parameters: coordinates, curves, widths, colors, and opacity. In our codebase, this is modeled by StrokeGene and Painting.

🎨 Phenotype (The Image)

The 2D raster image resulting from executing drawing commands sequentially onto a Skia canvas. The fitness function evaluates the phenotype, not the genotype directly.

💡 Why Vector Primitives Over Raw Pixels?
If you mutated an array of 256×256 raw pixels independently, the search space would be \(256^{256 \times 256}\) — an astronomical impossibility to search. By compressing images into 100–150 vector brush strokes, we drastically reduce dimensionality while producing organic, painterly aesthetic results.

2 Quadratic Bézier Curves in Skia

Straight lines look mechanical. Natural brush strokes curve, bend, and trail off. In Skia, the most efficient curved stroke primitive is the Quadratic Bézier curve, defined by 3 points:

  • Start Point \((x_0, y_0)\): Where the brush touches down.
  • Control Point \((x_c, y_c)\): An off-curve attractor that pulls the curve toward it.
  • End Point \((x_1, y_1)\): Where the brush lifts off.

Mathematically, for \(t \in [0, 1]\), the curve point \(B(t)\) is:

\[ B(t) = (1 - t)^2 P_0 + 2(1 - t)t P_c + t^2 P_1 \]

In Skiko, drawing a quadratic Bézier curve requires two method calls on an org.jetbrains.skia.Path:

Kotlin (Skiko Path API) 
path.reset()
path.moveTo(x0, y0)
path.quadTo(xc, yc, x1, y1)
canvas.drawPath(path, paint)

3 The StrokeGene Class

Let's inspect StrokeGene.kt in your project. Each gene captures geometry, stroke width, and 32-bit RGBA color:

src/main/kotlin/StrokeGene.kt 
package org.jetbrains.skia

data class StrokeGene(
    val x0: Float,
    val y0: Float,
    val xc: Float,
    val yc: Float,
    val x1: Float,
    val y1: Float,
    val strokeWidth: Float,
    val r: Int,
    val g: Int,
    val b: Int,
    val a: Int,
) {
    fun render(
        canvas: Canvas,
        paint: Paint,
        path: Path,
    ) {
        paint.color = Color.makeARGB(a, r, g, b)
        paint.strokeWidth = strokeWidth
        paint.mode = PaintMode.STROKE
        paint.strokeCap = PaintStrokeCap.ROUND
        paint.isAntiAlias = true

        path.reset()
        path.moveTo(x0, y0)
        path.quadTo(xc, yc, x1, y1)
        canvas.drawPath(path, paint)
    }
}
⚡ Performance Note: Buffer Reuse
Notice that render() accepts pre-allocated instances of Paint and Path rather than creating new ones inside each call. In genetic programming where thousands of evaluations occur per second, allocating temporary objects inside the render path triggers JVM Garbage Collection pauses. Reusing mutable buffers maintains 60+ FPS rendering and maximizes evolutionary throughput.

4 The Painting Chromosome

An individual artwork candidate is represented in Painting.kt as a list of strokes:

src/main/kotlin/Painting.kt 
data class Painting(
    val strokes: List,
    val error: Long = Long.MAX_VALUE,
) {
    fun render(
        canvas: Canvas,
        width: Float,
        height: Float,
        paint: Paint,
        path: Path,
        backgroundColor: Int = Color.WHITE,
    ) {
        // 1. Draw base coat
        paint.color = backgroundColor
        paint.mode = PaintMode.FILL
        canvas.drawRect(Rect.makeWH(width, height), paint)

        // 2. Draw brush strokes in sequential order
        for (stroke in strokes) {
            stroke.render(canvas, paint, path)
        }
    }
}

Order matters! Because strokes are rendered with alpha transparency (a < 255), overlapping strokes blend optically. Drawing stroke A before stroke B yields a different final pixel buffer than drawing stroke B before stroke A.

6 Stochastic Mutation Operators

How do we create variation without destroying established structure? In Painting.kt, the mutate() method applies small probabilistic perturbations:

Mutation Operators in Painting.kt 
fun mutate(width: Float, height: Float): Painting {
    val newStrokes = strokes.toMutableList()
    val roll = Random.nextFloat()

    when {
        // 75% chance: Mutate an existing stroke's parameters
        roll < 0.75f -> {
            val idx = Random.nextInt(newStrokes.size)
            newStrokes[idx] = newStrokes[idx].mutate(width, height)
        }
        // 15% chance: Swap order of two strokes (layering change)
        roll < 0.90f -> {
            val i = Random.nextInt(newStrokes.size)
            val j = Random.nextInt(newStrokes.size)
            Collections.swap(newStrokes, i, j)
        }
        // 10% chance: Replace a stroke completely with random one
        else -> {
            val idx = Random.nextInt(newStrokes.size)
            newStrokes[idx] = StrokeGene.random(width, height)
        }
    }
    return Painting(newStrokes)
}
💡 Why Keep Mutation Steps Small?
If you mutate too aggressively (e.g., throwing strokes to completely random coordinates on every generation), the evolutionary algorithm behaves like random guessing, and the acceptance rate drops below 1%. Small, localized perturbations allow the hill climber to fine-tune subtle gradients and edge alignments.
