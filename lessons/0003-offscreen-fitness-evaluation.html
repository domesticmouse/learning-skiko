Part 3 • Fitness & Evaluation

Headless Bitmaps & Offscreen Fitness Evaluation

Build a high-throughput fitness evaluator in Kotlin using headless Skia Bitmaps, understand direct pixel byte buffer comparisons, and eliminate memory allocation overhead in your inner loop.

1 The Fitness Objective Function

In an evolutionary algorithm, the fitness function is the mathematical compass that guides mutation selection. Without human judgment in the loop, the algorithm requires a deterministic scalar value indicating how closely a candidate painting matches the target image.

In image evolution, our objective is to minimize difference (also known as the error or loss function):

\[ \text{Fitness Error} = \sum_{x, y} \text{Distance}(\text{CandidatePixel}(x, y), \text{TargetPixel}(x, y)) \]

A lower error score means a closer visual approximation. An error of 0 would represent an identical pixel-for-pixel duplicate.

2 L1 Manhattan vs. L2 Euclidean Distance

When comparing two RGB color vectors \((R_1, G_1, B_1)\) and \((R_2, G_2, B_2)\), there are two common metrics:

📐 L1 Distance (Manhattan)

\[ \Delta = |R_1 - R_2| + |G_1 - G_2| + |B_1 - B_2| \]

Pros: Extremely fast on the CPU, requires no squaring or square root, uses simple subtraction and bitwise masks.

📏 L2 Distance (Euclidean / MSE)

\[ \Delta = (R_1 - R_2)^2 + (G_1 - G_2)^2 + (B_1 - B_2)^2 \]

Pros: Penalizes large individual pixel discrepancies more heavily, but requires multiplication and risks integer overflow on large images.

For our painter engine running thousands of evaluations per second, L1 Manhattan distance is the superior choice, delivering exceptional visual convergence with minimal CPU cycles.

3 Headless Skia Bitmaps

Unlike the windowed canvas in Lesson 1 which renders onto an AWT JFrame at 60 FPS, the fitness evaluator must run headlessly (without a visible GUI window) as fast as the CPU allows.

Skia allows allocating an in-memory pixel buffer called a Bitmap and binding a Canvas directly to it:

Headless Offscreen Allocation 
import org.jetbrains.skia.Bitmap
import org.jetbrains.skia.Canvas

// 1. Allocate an in-memory 32-bit ARGB raster bitmap
val bitmap = Bitmap().apply { allocN32Pixels(256, 256) }

// 2. Wrap the bitmap in a Canvas for drawing commands
val canvas = Canvas(bitmap)

// 3. Render strokes into the bitmap
candidatePainting.render(canvas, 256f, 256f, paint, path)

// 4. Extract raw byte array of pixels
val pixelBytes: ByteArray? = bitmap.readPixels(bitmap.imageInfo)

4 The Evaluator Class Architecture

Now examine Evaluator.kt in your workspace:

src/main/kotlin/Evaluator.kt 
class Evaluator(
    val width: Int,
    val height: Int,
    val targetBytes: ByteArray,
    val backgroundColor: Int = Color.WHITE,
) {
    // Reusable offscreen buffers — allocated ONCE!
    private val bitmap = Bitmap().apply { allocN32Pixels(width, height) }
    private val canvas = Canvas(bitmap)
    private val paint = Paint()
    private val path = Path()

    fun evaluate(painting: Painting): Long {
        // 1. Render candidate painting offscreen
        painting.render(
            canvas = canvas,
            width = width.toFloat(),
            height = height.toFloat(),
            paint = paint,
            path = path,
            backgroundColor = backgroundColor,
        )

        // 2. Read pixel buffer
        val candidateBytes = bitmap.readPixels(bitmap.imageInfo) ?: return Long.MAX_VALUE

        // 3. High-speed L1 Manhattan distance across bytes
        var diff = 0L
        val totalBytes = width * height * 4
        var i = 0
        while (i < totalBytes) {
            val bDiff = Math.abs((candidateBytes[i].toInt() and 0xFF) - (targetBytes[i].toInt() and 0xFF))
            val gDiff = Math.abs((candidateBytes[i + 1].toInt() and 0xFF) - (targetBytes[i + 1].toInt() and 0xFF))
            val rDiff = Math.abs((candidateBytes[i + 2].toInt() and 0xFF) - (targetBytes[i + 2].toInt() and 0xFF))

            diff += (bDiff + gDiff + rDiff)
            i += 4 // Skip alpha channel since background is opaque
        }
        return diff
    }
}
⚠️ Kotlin Byte Signedness Gotcha
In Kotlin/Java, Byte is signed (\(-128\) to \(127\)). When calculating color differences, you must convert to unsigned integers using b.toInt() and 0xFF before subtracting, otherwise a channel value like \(200\) (represented as \(-56\)) will produce distorted arithmetic!

6 TargetImage Loading & Rescaling

In TargetImage.kt, external PNG/JPEG files are loaded and rescaled to the simulation dimension (typically \(256 \times 256\)). If no file path is supplied in CLI arguments, it falls back to a procedurally generated geometric test target.

💡 Why 256×256 Resolution?
A \(256 \times 256\) canvas has \(65,536\) pixels (\(262,144\) bytes). A modern CPU can evaluate this in ~\(0.2\) milliseconds (over 4,000 evaluations/sec). An unscaled \(4000 \times 3000\) camera photo would drop throughput to 20 evals/sec, grinding evolution to a halt.
