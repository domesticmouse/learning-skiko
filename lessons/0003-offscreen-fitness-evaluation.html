Part 3 • Fitness & Evaluation

Headless Bitmaps & Offscreen Fitness Evaluation

Build a high-throughput fitness evaluator in Kotlin using headless Skia Bitmaps, understand direct pixel byte buffer comparisons, and eliminate memory allocation overhead in your inner loop.

1 The Fitness Objective Function

In an evolutionary algorithm, the fitness function is the mathematical compass that guides mutation selection. Without human judgment in the loop, the algorithm requires a deterministic scalar value indicating how closely a candidate painting matches the target image.

In image evolution, our objective is to minimize difference (also known as the error or loss function):

\[ \text{Fitness Error} = \sum_{x, y} \text{Distance}(\text{CandidatePixel}(x, y), \text{TargetPixel}(x, y)) \]

A lower error score means a closer visual approximation. An error of 0 would represent an identical pixel-for-pixel duplicate.

2 L1 Manhattan vs. L2 Sum of Squared Differences (SSD)

When comparing two RGB color vectors \((R_1, G_1, B_1)\) and \((R_2, G_2, B_2)\), there are two classical distance metrics:

📐 L1 Distance (Manhattan)

\[ \Delta_{L1} = |R_1 - R_2| + |G_1 - G_2| + |B_1 - B_2| \]

Characteristics: Treats all errors linearly—one pixel off by 60 counts the same as ten pixels off by 6. Can leave harsh, high-contrast color artifacts unpunished.

📏 L2 Squared Distance (SSD)

\[ \Delta_{L2}^2 = (R_1 - R_2)^2 + (G_1 - G_2)^2 + (B_1 - B_2)^2 \]

Characteristics: Penalizes large individual pixel discrepancies quadratically (\(60^2 = 3600\) vs \(10 \times 6^2 = 360\)) and avoids slow sqrt() calls by summing squared differences directly into a 64-bit Long.

In our painter engine (steps/0003-offscreen-fitness-evaluation/src/main/kotlin/Evaluator.kt), we use L2 Sum of Squared Differences (SSD): integer multiplication (d * d) is single-cycle on modern CPUs, branchless (unlike Math.abs), and strongly pressures the algorithm to eliminate glaring color mismatches first.

3 Headless Skia Bitmaps

Unlike the windowed canvas in Lesson 1 which renders onto an AWT JFrame at 60 FPS, the fitness evaluator must run headlessly (without a visible GUI window) as fast as the CPU allows.

Skia allows allocating an in-memory pixel buffer called a Bitmap and binding a Canvas directly to it:

Headless Offscreen Allocation 
import org.jetbrains.skia.Bitmap
import org.jetbrains.skia.Canvas

// 1. Allocate an in-memory 32-bit ARGB raster bitmap
val bitmap = Bitmap().apply { allocN32Pixels(256, 256) }

// 2. Wrap the bitmap in a Canvas for drawing commands
val canvas = Canvas(bitmap)

// 3. Render strokes into the bitmap
candidatePainting.render(canvas, 256f, 256f, paint, path)

// 4. Extract raw byte array of pixels
val pixelBytes: ByteArray? = bitmap.readPixels(bitmap.imageInfo)

4 The Evaluator Class Architecture

Now examine steps/0003-offscreen-fitness-evaluation/src/main/kotlin/Evaluator.kt in your workspace:

src/main/kotlin/Evaluator.kt 
import org.jetbrains.skia.Bitmap
import org.jetbrains.skia.Canvas
import org.jetbrains.skia.Color
import org.jetbrains.skia.Paint
import org.jetbrains.skia.Path

class Evaluator(
    val width: Int,
    val height: Int,
    val targetBytes: ByteArray,
    val backgroundColor: Int = Color.WHITE,
) {
    // Reusable offscreen buffers — allocated ONCE per Evaluator!
    // Disambiguate with this@Evaluator so width/height aren't shadowed by Bitmap properties inside .apply
    private val bitmap = Bitmap().apply { allocN32Pixels(this@Evaluator.width, this@Evaluator.height) }
    private val canvas = Canvas(bitmap)
    private val paint = Paint()
    private val path = Path()

    fun evaluate(painting: Painting): Long {
        // 1. Render painting onto offscreen canvas
        painting.render(
            canvas = canvas,
            width = width.toFloat(),
            height = height.toFloat(),
            paint = paint,
            path = path,
            backgroundColor = backgroundColor,
        )

        // 2. Read pixel buffer
        val candidateBytes = bitmap.readPixels(bitmap.imageInfo) ?: return Long.MAX_VALUE

        // 3. Compute Sum of Squared Differences (L2 SSD)
        var totalError = 0L
        val len = candidateBytes.size
        var i = 0
        while (i < len) {
            val d0 = (candidateBytes[i].toInt() and 0xFF) - (targetBytes[i].toInt() and 0xFF)
            val d1 = (candidateBytes[i + 1].toInt() and 0xFF) - (targetBytes[i + 1].toInt() and 0xFF)
            val d2 = (candidateBytes[i + 2].toInt() and 0xFF) - (targetBytes[i + 2].toInt() and 0xFF)
            totalError += (d0 * d0) + (d1 * d1) + (d2 * d2)
            i += 4 // Step 4 bytes per pixel (skip alpha byte i+3)
        }

        return totalError
    }
}
💡 Memory Layout: Why Step by 4 Bytes (i += 4)?
allocN32Pixels allocates 32-bit pixels in native BGRA_8888 byte order on little-endian CPUs (4 bytes per pixel: Blue at i, Green at i+1, Red at i+2, Alpha at i+3). Because Painting.render() starts with an opaque base coat (Color.WHITE), every composited pixel has Alpha == 255, so we only need to compare the first three color bytes of each 4-byte stride.
⚠️ Kotlin Byte Signedness Gotcha
In Kotlin/Java, Byte is signed (\(-128\) to \(127\)). When calculating color differences, you must convert to unsigned integers using b.toInt() and 0xFF before subtracting, otherwise a channel value like \(200\) (represented as \(-56\)) will produce distorted arithmetic!

6 TargetImage Loading & Rescaling

In steps/0003-offscreen-fitness-evaluation/src/main/kotlin/TargetImage.kt, external PNG/JPEG files are loaded and rescaled to the simulation dimension (typically \(256 \times 256\)). If no file path is supplied in CLI arguments, it falls back to a procedurally generated geometric test target.

💡 Why 256×256 Resolution?
A \(256 \times 256\) canvas has \(65,536\) pixels (\(262,144\) bytes). A modern CPU can evaluate this in ~\(0.2\) milliseconds (over 4,000 evaluations/sec). An unscaled \(4000 \times 3000\) camera photo would drop throughput to 20 evals/sec, grinding evolution to a halt.

7 Automated Testing & Verification

We write unit tests with kotlin.test to verify:

  • Zero error when evaluating an identical white painting against an all-white target.
  • Exact L2 SSD maximum error calculation when comparing pure white against pure black (\(\text{SSD} = W \times H \times 3 \times 255^2\)).
  • Non-negative error guarantees across arbitrary procedural targets and random chromosomes.
  • Valid dimensions and byte array stride for procedural target generation.
src/test/kotlin/EvaluatorTest.kt 
import org.jetbrains.skia.Color
import kotlin.test.Test
import kotlin.test.assertEquals
import kotlin.test.assertTrue

class EvaluatorTest {
    private val width = 64
    private val height = 64

    @Test
    fun testTargetImageProceduralGeneration() {
        val target = TargetImage.loadOrGenerate(null, width, height)
        assertEquals(width, target.width)
        assertEquals(height, target.height)
        assertEquals(width * height * 4, target.pixelBytes.size)
        assertTrue(target.sourceDescription.contains("Procedural"), "Fallback should have procedural description")
    }

    @Test
    fun testEvaluatorZeroErrorOnIdenticalWhite() {
        val whiteBytes = ByteArray(width * height * 4) { -1 } // 0xFF in signed byte
        val evaluator = Evaluator(width, height, whiteBytes, backgroundColor = Color.WHITE)

        val emptyPainting = Painting(strokes = emptyList())
        val error = evaluator.evaluate(emptyPainting)
        assertEquals(0L, error, "An empty white painting against an all-white target must yield error 0")
    }

    @Test
    fun testEvaluatorMaxErrorOnInvertedBlackAndWhite() {
        val blackBytes = ByteArray(width * height * 4)
        for (i in 0 until (width * height)) {
            blackBytes[i * 4 + 3] = -1 // Alpha = 255
        }

        val evaluator = Evaluator(width, height, blackBytes, backgroundColor = Color.WHITE)
        val emptyPainting = Painting(strokes = emptyList())
        val error = evaluator.evaluate(emptyPainting)

        val expected = (width * height).toLong() * 3L * (255L * 255L)
        assertEquals(expected, error, "Error against opposite color must match exact SSD formula")
    }

    @Test
    fun testEvaluatorNonNegativeError() {
        val target = TargetImage.loadOrGenerate(null, width, height)
        val evaluator = Evaluator(width, height, target.pixelBytes)
        val painting = Painting.createRandom(20, width.toFloat(), height.toFloat())
        val error = evaluator.evaluate(painting)
        assertTrue(error >= 0L, "Fitness error must be non-negative")
    }
}
