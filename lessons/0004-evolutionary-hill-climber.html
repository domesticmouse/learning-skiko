Part 4 • Evolutionary Algorithm

The Evolutionary Loop & Hill Climber Strategy

Implement an asynchronous (1+1) Evolutionary Strategy in Kotlin, coordinate lock-free state across background worker threads, and understand genetic convergence dynamics.

1 The (1+1) Hill Climber Strategy

In classic genetic algorithms for symbolic optimization, you typically maintain a population of hundreds of candidates and apply sexual crossover (slicing two genomes in half and splicing them together).

However, for image approximation with hundreds of semi-transparent vector strokes, crossover is disastrous: stroke #42 from Parent A was tuned to blend specifically over strokes #1–41 of Parent A. Splicing it into Parent B produces visual disharmony and sharp fitness regressions.

Instead, the gold standard in evolutionary art is the (1+1) Evolutionary Strategy (also known as a stochastic hill climber with mutation):

1
Champion
Maintain current best painting candidate.
⬇
2
Stochastic Mutation
Clone champion and mutate a single gene or stroke order.
⬇
3
Offscreen Evaluation
Compute L2 squared pixel difference (SSD) against target image.
⬇
4
Selection Decision (with Neutral Drift)
If mutant error ≤ champion error, mutant becomes new champion! Else discard.
💡 Why ≤ Instead of Strict <? (Neutral Drift)
Notice that Step 4 accepts a mutant even when its error is equal (mutantError <= champion.error). In evolutionary computation, this is called neutral drift. If a small stroke is currently hidden beneath a larger opaque stroke, mutating its position changes zero visible pixels (\(\Delta\text{Error} = 0\)). Strict inequality (<) would trap that stroke forever, whereas ≤ allows it to drift across flat fitness plateaus until it emerges into an uncovered region where it can reduce error!

2 Multi-Threaded Architecture

In a graphical desktop app, the AWT Event Dispatch Thread (EDT) is responsible for handling OS window events, keyboard shortcuts, and rendering frames at 60 FPS.

⚠️ Never Run Evolution on the UI Thread!
If you run the evolutionary loop on the main UI thread, your desktop window will immediately freeze and stop responding to mouse or keyboard events.

We spawn an independent, high-priority background worker thread:

Worker Thread Spawning 
thread(name = "GeneticPainter-Evolution", isDaemon = true) {
    while (running.get()) {
        if (paused.get()) {
            Thread.sleep(50)
            continue
        }
        // Mutate, evaluate, and publish champion...
    }
}

3 Lock-Free State Synchronization

Because the worker thread generates thousands of mutations per second while the UI thread reads the current best painting at 60 FPS, we must prevent race conditions without using heavy, blocking locks.

Kotlin and the JVM provide lock-free java.util.concurrent.atomic primitives:

  • AtomicBoolean: Used for running and paused control flags.
  • AtomicLong: Used for generations, acceptedMutations, and currentEvalsPerSec.
  • AtomicReference<Painting>: Holds the pointer to the latest accepted champion painting. The UI thread reads this pointer with zero synchronization locks:
Lock-Free Atomic Reference 
private val bestPaintingRef = AtomicReference()

fun getBestPainting(): Painting = bestPaintingRef.get()

private fun updateBestPainting(newChampion: Painting) {
    bestPaintingRef.set(newChampion)
}
🔒 Why Immutability Makes AtomicReference Safe
AtomicReference only swaps the object reference atomically—it does not lock the fields inside Painting. This is 100% thread-safe only because we designed Painting and StrokeGene in Lesson 2 as immutable data classes! Once the worker thread publishes a Painting via bestPaintingRef.set(currentBest), it never mutates that instance's strokes list in place, so the UI thread can iterate over strokes at 60 FPS without ConcurrentModificationException.

4 The GeneticPainter Engine

Examine the core loop in steps/0004-evolutionary-hill-climber/src/main/kotlin/GeneticPainter.kt in your project:

src/main/kotlin/GeneticPainter.kt 
// Create a mutated candidate from the current champion
val candidate = currentBest.mutate(width.toFloat(), height.toFloat(), rng)

// Evaluate candidate using L2 SSD
val candidateError = evaluator.evaluate(candidate)
generations.incrementAndGet()
localEvals++

// Selection: Accept if better or equal (neutral drift can help cross plateaus)
if (candidateError <= currentBest.error) {
    currentBest = candidate.copy(error = candidateError)
    bestPaintingRef.set(currentBest)
    acceptedMutations.incrementAndGet()
}

6 Understanding Convergence Phases

When you run the algorithm, you will observe distinct stages of convergence:

🚀 Phase 1: Macro Approximation (0–5k gens)

Acceptance rate is high (~15–30%). Large strokes cover the canvas, establishing the dominant color palette and rough silhouettes.

🔬 Phase 2: Micro Refinement (5k–100k+ gens)

Acceptance rate drops to ~1–3%. Mutations fine-tune individual edge curves, subtle shading gradients, and highlight accents.

7 Automated Testing & Verification

Multi-threaded evolutionary loops require verification of thread coordination, monotonic fitness convergence, and boundary clamps on stroke budget tuning.

src/test/kotlin/GeneticPainterTest.kt 
import kotlin.test.Test
import kotlin.test.assertEquals
import kotlin.test.assertTrue

class GeneticPainterTest {
    private val width = 64
    private val height = 64

    @Test
    fun testInitializationAndChampionPresence() {
        val target = TargetImage.loadOrGenerate(null, width, height)
        val painter = GeneticPainter(target = target, initialStrokeCount = 30)

        assertEquals(width, painter.width)
        assertEquals(height, painter.height)
        assertEquals(30, painter.strokeCount)
        assertTrue(painter.initialError > 0L, "Initial error must be positive")

        val best = painter.getBestPainting()
        assertEquals(30, best.strokes.size)
        assertEquals(painter.initialError, best.error)
    }

    @Test
    fun testEvolutionMonotonicFitnessImprovement() {
        val target = TargetImage.loadOrGenerate(null, width, height)
        val painter = GeneticPainter(target = target, initialStrokeCount = 25)

        painter.start()
        val start = System.currentTimeMillis()
        while (painter.generations.get() < 100L && System.currentTimeMillis() - start < 3000L) {
            Thread.sleep(20)
        }
        painter.stop()

        assertTrue(painter.generations.get() >= 50L, "Should have executed at least 50 generations")
        val finalBest = painter.getBestPainting()
        assertTrue(
            finalBest.error <= painter.initialError,
            "Best error (${finalBest.error}) must be <= initial error (${painter.initialError})"
        )
    }

    @Test
    fun testPauseResumeLifecycle() {
        val target = TargetImage.loadOrGenerate(null, width, height)
        val painter = GeneticPainter(target = target, initialStrokeCount = 20)

        assertEquals(false, painter.paused.get())
        painter.togglePause()
        assertEquals(true, painter.paused.get())
        painter.togglePause()
        assertEquals(false, painter.paused.get())
    }

    @Test
    fun testAdjustStrokesBoundaryClamping() {
        val target = TargetImage.loadOrGenerate(null, width, height)
        val painter = GeneticPainter(target = target, initialStrokeCount = 50)

        painter.adjustStrokes(20)
        assertEquals(70, painter.strokeCount)
        assertEquals(70, painter.getBestPainting().strokes.size)

        painter.adjustStrokes(-1000) // Lower bound clamp at 10
        assertEquals(10, painter.strokeCount)
        assertEquals(10, painter.getBestPainting().strokes.size)

        painter.adjustStrokes(1000) // Upper bound clamp at 500
        assertEquals(500, painter.strokeCount)
        assertEquals(500, painter.getBestPainting().strokes.size)
    }

    @Test
    fun testReset() {
        val target = TargetImage.loadOrGenerate(null, width, height)
        val painter = GeneticPainter(target = target, initialStrokeCount = 20)

        painter.generations.set(500)
        painter.acceptedMutations.set(120)
        painter.reset()

        assertEquals(0L, painter.generations.get())
        assertEquals(0L, painter.acceptedMutations.get())
    }
}

8 Knowledge Check

Check your storage strength on concurrency and evolutionary strategy design.

Why is crossover omitted in favor of a (1+1) mutation strategy for vector art?
Kotlin collections lack crossover support.
Crossover doubles fitness evaluation time.
Splicing strokes destroys visual layering.
Atomic references cannot synchronize populations.
